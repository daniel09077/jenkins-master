
# JAVA-BASED-CI-PIPELINE-USING-DOCKER-CONTAINERS

A containerized Java Continuous Integration (CI) environment designed to automate the workflow from source code changes through build, testing, code quality analysis, and artifact publication.

The project was built on an Ubuntu-based homelab environment using GitHub, Jenkins, Maven, SonarQube, Nexus Repository, Docker, and Tailscale.

When code is pushed to GitHub, a webhook triggers Jenkins. Because Jenkins is hosted inside a private homelab network, Tailscale was used to provide the network connectivity required for the webhook to reach the Jenkins environment.

Jenkins then checks out the source code, builds the Java application with Maven, runs the project's tests, performs code quality analysis with SonarQube, and publishes the resulting Maven artifact to Nexus Repository.

* **Add Docker's GPG Key:**\
First, create the directory where APT stores trusted repository keys:
    ```bash
    sudo install -m 0755 -d /etc/apt/keyrings
    ```
* **Download Docker's signing key:**  
    ```bash 
    sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
    ```

**Break it down:**

- curl: Downloads data.\
-fsSL: 
f → fail if the request fails
s → silent mode
S → show errors
L → follow redirects
-o Save output to a file.

**Change the permission of the key file:** 

```bash
    sudo chmod a+r /etc/apt/keyrings/docker.asc
```
**Meaning:**
"Allow all users/processes to read this key."

## Jenkins Configuration

Jenkins is responsible for orchestrating the CI pipeline.

After the Jenkins container starts, access Jenkins through the exposed port:

```text
http://<server-ip>:<jenkins-port>
```

Retrieve the initial administrator password if required:

```bash
docker exec <jenkins-container> cat /var/jenkins_home/secrets/initialAdminPassword
```

Complete the initial Jenkins setup and install the required plugins.

The project uses Jenkins functionality for:

* Pipeline execution
* GitHub integration
* Credentials management
* Config File Provider
* Maven integration
* SonarQube integration

### Jenkins Credentials

Credentials are stored in Jenkins rather than hardcoded in the Jenkinsfile.

The pipeline uses:

| Credential ID       | Type              | Purpose                        |
| ------------------- | ----------------- | ------------------------------ |
| `test-sonarqube-id` | Secret Text       | SonarQube authentication token |
| `nexus-repo`        | Username/Password | Nexus artifact deployment      |

## SonarQube Configuration

SonarQube is used for static code analysis.

Access the SonarQube interface through the exposed port:

```text
http://<server-ip>:<sonarqube-port>
```

Create a project using:

```text
Project Key: jenkins-sonarqube
Project Name: jenkins-sonarqube
```

Generate a SonarQube authentication token and store it in Jenkins Credentials as a **Secret Text** credential.

The pipeline retrieves the token at runtime:

```groovy
withCredentials([
    string(
        credentialsId: 'test-sonarqube-id',
        variable: 'SONAR_TOKEN'
    )
])
```

The token is then passed to Maven without hardcoding it:

```bash
-Dsonar.token=$SONAR_TOKEN
```

---

## Nexus Repository Configuration

Nexus Repository is used to store the Maven artifacts generated by the pipeline.

Access Nexus through the exposed port:

```text
http://<server-ip>:<nexus-port>
```

Create a **Maven Hosted Repository** for the generated artifacts.

Example:

```text
maven2-hosted
```

Create a dedicated Nexus user for Jenkins and provide it with the permissions required to publish artifacts to the Maven hosted repository.

Store the Nexus username and password in Jenkins Credentials using the credential ID:

```text
nexus-repo
```

## Maven Authentication

The Maven `settings.xml` configuration is managed through the **Jenkins Config File Provider plugin**.

The managed configuration is identified as:

```text
maven-config-file
```

The pipeline loads the configuration during the deployment stage:

```groovy
configFileProvider([
    configFile(
        fileId: 'maven-config-file',
        variable: 'MAVEN_SETTINGS'
    )
])
```

The Nexus credentials are injected at runtime using Jenkins Credentials:

```groovy
withCredentials([
    usernamePassword(
        credentialsId: 'nexus-repo',
        usernameVariable: 'NEXUS_USER',
        passwordVariable: 'NEXUS_PASS'
    )
])
```

Maven then uses the managed settings file during deployment:

```bash
mvn deploy -s $MAVEN_SETTINGS
```

This keeps the credentials and Maven configuration outside the source repository.

## GitHub Webhook

GitHub triggers the Jenkins pipeline whenever changes are pushed to the repository.

Because Jenkins is running inside a private homelab network, Tailscale was used to provide the required network connectivity.

Configure the reachable Jenkins webhook endpoint in:

**GitHub → Repository → Settings → Webhooks**

Configure the webhook to trigger on push events.

The workflow is:

```text
Git Push
   ↓
GitHub Webhook
   ↓
Jenkins
```

---

## Pipeline Workflow

Once configured, the pipeline follows this process:

```text
1. GitHub Push
       ↓
2. Webhook triggers Jenkins
       ↓
3. Jenkins checks out source code
       ↓
4. Maven validates/builds project
       ↓
5. Maven runs tests
       ↓
6. SonarQube performs code analysis
       ↓
7. Maven deploys artifact
       ↓
8. Nexus stores artifact
```

The Java project is located inside the `java` directory, so Maven commands are executed from that directory during the pipeline.

## Troubleshooting

### Maven not found

If Jenkins returns:

```text
mvn: executable file not found in $PATH
```

verify that Maven is available in the Jenkins build environment.

### Maven project directory

The `pom.xml` is located inside the `java` directory rather than the repository root.

The Jenkins pipeline therefore executes Maven commands from the configured project directory.

### Jenkins persistence

Jenkins uses persistent storage mounted to:

```text
/var/jenkins_home
```

This preserves Jenkins configuration and data when the container is recreated.
